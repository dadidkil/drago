# ТОП «Драго» — инструкция для Claude Code

Монорепозиторий: сайт, личный кабинет, админ-панель, Telegram- и VK-боты, воркер уведомлений для трудового отряда
подростков ТОП «Драго» (Москва, РСО). Весь код написан и проверен; CI зелёный. Задача этой сессии обычно —
**развернуть и сопровождать систему на сервере**.

## Если сессия запущена НЕ на сервере (на компьютере пользователя)

Сервер доступен по SSH без пароля (ключ): `ssh -o BatchMode=yes root@2.56.90.240 hostname`. Все серверные команды
выполняй удалённо, например `ssh root@2.56.90.240 'cd /opt/drago && make audit'`. Длинные операции (`make deploy`)
запускай в tmux на сервере: `ssh root@2.56.90.240 'tmux new -d -s deploy "cd /opt/drago && make deploy 2>&1 | tee /root/deploy.log"'`,
затем читай `/root/deploy.log`. Правила ниже действуют так же. Секреты из `/opt/drago/.env` в чат не выводи.

## Порядок деплоя (кратко; детали и проверки — в docs/deployment.md)

```bash
cd /opt/drago
make audit                 # read-only; раздел «DNS домена» должен показать совпадение A-записи с IP сервера
make backup-existing       # бэкап всего, что уже есть на сервере — ДО любых изменений
make bootstrap             # Docker, fail2ban; при ISPmanager UFW не ставится
make secrets               # создаёт .env (600) со стойкими секретами; НЕ перезаписывает существующий
# заполнить .env: ACME_EMAIL, (позже) SMTP_*, TELEGRAM_*, VK_*, MAIL_PROVIDER/ISPMANAGER_*
make deploy                # сборка → бэкап → миграции → запуск → healthcheck
make nginx-proxy           # подключить сайт к nginx ISPmanager (нужен SSL сайта в панели)
make invite-admin email=…  # одноразовая ссылка суперадмина — отдать пользователю лично
```

Сайт сначала должен получить SSL в ISPmanager (шаг 5.2 гайда). Это возможно только после исправления DNS.

## Правила работы на сервере

Это production-сервер. В системе будут персональные данные несовершеннолетних.

**Делай сам (безопасно и обратимо):** read-only диагностика; `make audit`, `make ps`, `make logs`; сборка и `make deploy`;
`make nginx-proxy` (сам проверяет `nginx -t` и откатывается); `make backup`; правки кода в репозитории.

**Сначала спроси пользователя и получи явное «да»:**
- любое удаление или остановка того, что уже было на сервере: сайты и службы ISPmanager, nginx/apache, базы, тома Docker, файлы;
- изменение брандмауэра. Перед любым запретом убедись, что порт SSH разрешён;
- `03-harden-ssh.sh` (отключение входа по паролю). Только после того, как пользователь подтвердил вход по ключу в новом окне;
- перезагрузка сервера и `systemctl restart docker` (рвёт работу сайта на 10–20 с);
- `make restore`, изменения в `.env` на работающей системе, смена `APP_ENCRYPTION_KEY` (**никогда**: сломает 2FA всем);
- создание пользователей или ящиков от имени отряда и массовые рассылки.

**Никогда:**
- не выводи секреты в чат (`cat .env`, пароли, токены) — показывай только имена переменных;
- не коммить `.env`, дампы, бэкапы, загруженные файлы;
- не редактируй сгенерированные ISPmanager конфиги nginx: только `vhosts-resources` через `make nginx-proxy`;
- не открывай наружу порты 3000/3002/5432/6379;
- не отключай 2FA-требование для командного состава и проверки прав.

**Что может сделать только пользователь** (попроси и дай точную инструкцию):
- DNS в REG.RU — таблицы в `docs/dns-records.md`;
- PTR и открытие порта 25 — тикет хостеру, текст в гайде (шаг 12.1);
- вход в ISPmanager через браузер, если нужны действия в интерфейсе: SSL, почтовый домен, брандмауэр;
- @BotFather и настройки сообщества VK (шаги 13–14);
- установка 2FA в своём телефоне; хранение копии `.env` в менеджере паролей.

## Технические подсказки

- Режим трафика задаёт `REVERSE_PROXY` в `.env`: `ispmanager` (nginx панели → 127.0.0.1:3000/3002) или `caddy` (сервер
  без панели). Makefile и `deploy.sh` подхватывают его сами.
- Docker Hub из РФ бывает недоступен — образы по умолчанию идут с `mirror.gcr.io`; альтернатива —
  `public.ecr.aws/docker/library/...` через `NODE_IMAGE` / `POSTGRES_IMAGE` / `REDIS_IMAGE` / `CADDY_IMAGE`.
- `ACME_EMAIL` обязателен в `.env` даже в режиме ISPmanager (интерполяция compose).
- После изменения брандмауэра ISPmanager контейнеры могут потерять интернет → `systemctl restart docker`
  (только с согласия пользователя, см. правила).
- `pkill -f <шаблон>` может убить собственную оболочку, если шаблон встречается в тексте команды. Используй `[x]yz`-приём
  или PID.
- Проверки кода: `pnpm install && pnpm typecheck && pnpm test` (на сервере нужен Node 22 + pnpm; для деплоя не обязательны —
  всё собирается в Docker).
- Если меняешь код на сервере: коммить в `claude/amazing-maxwell-xkzunz`. Push возможен, только если на сервере
  настроены учётные данные GitHub; иначе опиши изменения пользователю и не оставляй сервер с незакоммиченными правками.
