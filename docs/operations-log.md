## 2026-09-24 — Диагностика ошибки Let's Encrypt в ISPmanager

- Симптом (скриншот владельца): «Проверка владения доменом — 95.163.244.138: Invalid response from
  http://dragotop.ru/.well-known/acme-challenge/…: 404».
- Проверено по DNS: NS `ns1/ns2.reg.ru`; `A dragotop.ru` и `A www.dragotop.ru` = **95.163.244.138** (TTL 21600);
  MX/TXT нет; `mail.dragotop.ru` — NXDOMAIN. PTR 2.56.90.240 → `academic-special-kestrel.ihchost.rocks`.
- Вывод: домен указывает не на сервер 2.56.90.240, Let's Encrypt проверял другой сервер.
- Действие владельца: сменить `A @` и `A www` в REG.RU на IP сервера с ISPmanager, подождать, повторить выпуск.
- Добавлено: проверка «DNS указывает на этот сервер» в `00-server-audit.sh`; `CLAUDE.md` для запуска Claude Code на
  сервере (Remote Control) — см. `deployment.md`, приложение В.

## 2026-09-24 (вечер) — Первый деплой: конфликт порта, SSL, DNS

- `make deploy` (владелец): образы собраны; экспорт образа оборвался — на диске 30 ГБ оставалось 5,2 ГБ, кэш сборки
  Docker занимал 14,7 ГБ. Добавлены: автоочистка кэша сборки при <8 ГБ, лимит кэша 4 ГБ, лёгкий образ `migrate`.
- `curl http://127.0.0.1:3000/api/health` на сервере вернул страницу 404 **другого сайта — genreless.ru** (Next.js,
  тот же сервер). Порт 3000 занят им; контейнер web «Драго» не смог его занять. Чужой сайт не трогали.
- Исправлено в коде: порты по умолчанию 3100/3102; `deploy.sh` проверяет порты и при конфликте с чужим процессом
  сам выбирает свободный и записывает в `.env`; `/api/health` отвечает `{"status":"ok","app":"drago"}`, и скрипты
  проверяют именно это (чтобы не принять чужое приложение за наше); `install-nginx-proxy.sh` подставляет порты из
  `.env` и отказывается проксировать домен на порт, где отвечает не «Драго».
- Браузер: `ERR_SSL_VERSION_OR_CIPHER_MISMATCH` на dragotop.ru — у сайта ещё нет сертификата.
- DNS: разные резолверы отдавали вперемешку 2.56.90.240 и старый 95.163.244.138 (TTL старой записи — 6 часов;
  из среды разработчика авторитетные ответы проверить не удалось — DNS там идёт через кэш). Проверить с сервера:
  `dig @ns1.reg.ru dragotop.ru A +norecurse` (флаг `aa`), затем выпуск Let's Encrypt.
