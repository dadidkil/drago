# Корпоративная почта @dragotop.ru

## Итог

**Сервер с ISPmanager (наш случай): основной вариант — C, почта ISPmanager.**
Ящики создаются автоматически из нашей админки через API панели, обслуживание (обновления Exim/Dovecot, антиспам,
Roundcube) берёт на себя панель. Условия: хостер дал **PTR** и открыл **порт 25**, а чек-лист доставки (внизу)
пройден.

**Запасной вариант — B: Яндекс 360 / VK WorkSpace.** Переходите на него, если хостер не даёт PTR или порт 25 либо
письма стабильно попадают в спам. Сайт переключается одной переменной: `MAIL_PROVIDER=manual`.

Вариант A (свой Stalwart) нужен только для сервера **без** панели: на сервере с ISPmanager он конфликтовал бы с
почтой панели за порт 25.

Общие риски почты на своём сервере (A и C) и почему B надёжнее по доставляемости:

1. **Доставляемость.** У нового IP VPS нулевая почтовая репутация. Gmail, Яндекс и Mail.ru режут такую почту
   в спам или отклоняют её, даже при корректных SPF/DKIM/DMARC. Прогрев IP занимает недели. Крупный провайдер
   даёт хорошую репутацию сразу.
2. **Порт 25 и PTR.** Многие VPS-хостинги по умолчанию блокируют исходящий порт 25, а PTR настраивается только через
   хостинг, а не через REG.RU. Без открытого порта и PTR свой сервер не сможет нормально отправлять почту.
3. **Безопасность аккаунтов подростков.** У провайдера есть антиспам, антифишинг, 2FA, обнаружение
   подозрительных входов и мобильные приложения. На своём сервере всё это нужно настраивать и сопровождать самим.
4. **Ресурсы VPS.** Stalwart с антиспамом и Roundcube занимают ещё 0,5–1 ГБ RAM. Рядом уже работают сайт, база
   и боты. Почта на том же сервере — ещё и единая точка отказа.
5. **152-ФЗ.** Провайдер с хранением данных в РФ закрывает требование локализации персональных данных граждан РФ.
   Gmail/Google Workspace для этого не подходят.
6. **Сопровождение.** Свой сервер — это обновления, мониторинг блок-листов, квоты, бэкапы ящиков и разбор жалоб
   на спам. В молодёжной организации без штатного администратора эта нагрузка быстро становится проблемой.

| Критерий | A. Stalwart (без панели) | B. Managed (Яндекс 360 / VK WorkSpace) | C. Почта ISPmanager |
|---|---|---|---|
| Доставляемость на Gmail/Яндекс/Mail.ru | риск, нужен прогрев IP | высокая с первого дня | риск, нужен прогрев IP |
| Зависимость от хостинга (порт 25, PTR) | критическая | нет | критическая |
| Автосоздание ящиков из админки | ✅ API Stalwart | ручное (`manual`) | ✅ API ISPmanager |
| Пароли не видны администратору | ✅ временный пароль — один раз владельцу | ✅ средствами провайдера | ✅ временный пароль — один раз владельцу |
| Веб-почта | Roundcube (в compose) | веб-интерфейс провайдера | Roundcube панели (`/roundcube`) |
| Обслуживание | самим | провайдер | панель (обновления, антиспам) |
| 2FA, мобильные приложения | частично | ✅ | IMAP/SMTP-клиенты; 2FA — нет |
| Стоимость | ресурсы VPS | по тарифу провайдера | входит в лицензию панели |
| Контроль над данными | полный | у провайдера (в РФ) | полный |

## Вариант C: почта ISPmanager (рекомендуется для этого сервера)

Пошагово — в [deployment.md, шаг 12](deployment.md#12-почта-dragotopru). Коротко:

1. Хостер: PTR `2.56.90.240 → mail.dragotop.ru`, открытый исходящий порт 25.
2. ISPmanager: сайт `mail.dragotop.ru` с сертификатом Let's Encrypt; почтовый домен `dragotop.ru` с DKIM и этим
   сертификатом.
3. DNS: MX, SPF, DKIM, DMARC ([dns-records.md](dns-records.md), раздел 2C).
4. `.env`: `MAIL_PROVIDER=ispmanager`, `ISPMANAGER_URL=https://host.docker.internal:1500`, `ISPMANAGER_USER` и
   `ISPMANAGER_PASSWORD` — пользователь-владелец почтового домена, **не root**; `ISPMANAGER_TLS_VERIFY=false` при
   самоподписанном сертификате панели.
5. Брандмауэр ISPmanager: 1500/tcp с `172.16.0.0/12` (сеть Docker), затем `systemctl restart docker`.
6. `/admin/integrations` → «ISPmanager API доступен, почтовый домен dragotop.ru найден».

Реализация — `packages/core/src/mail/ispmanager.ts`: POST на `/ispmgr` с `out=json`, функции `email.edit`
(создание и смена пароля), `email.suspend`, `email.resume`, `email.delete`, `emaildomain` (проверка). Пароли
передаются только в теле запроса, не в URL, поэтому не попадают в журналы панели. Покрыто тестами с mock-сервером.

## Как это реализовано в системе

- Модель `EmailAccount` хранит адрес, владельца, провайдера, статус и последнюю ошибку.
- `MailProvisioner` (`packages/core/src/mail/provisioner.ts`) — интерфейс с двумя реализациями:
  - `ispmanager` создаёт ящик, сбрасывает пароль, блокирует, разблокирует и удаляет его через API панели;
  - `stalwart` создаёт ящик, сбрасывает пароль, отключает и удаляет его через `/api/principal`;
  - `manual` только ведёт учёт, ящик создаётся у провайдера вручную.
- Админка `/admin/mail` (право `mail.manage`):
  - создать `имя.фамилия@dragotop.ru` для активного пользователя (адрес предлагается транслитом ФИО);
  - выпустить новый временный пароль, отключить или удалить ящик;
  - все действия пишутся в журнал аудита (`mail.create`, `mail.password_reset`, `mail.disable`, `mail.delete`).
- **Администратор никогда не видит пароль.** Сервер генерирует временный пароль (20 символов, ~115 бит) и передаёт его
  Stalwart. В БД пароль хранится только зашифрованным (AES-256-GCM, `APP_ENCRYPTION_KEY`) до 72 часов. Владелец видит
  его **один раз** в `/cabinet/mail`: после показа запись атомарно стирается. Истёкшие пароли стирает воркер.
- Владелец получает уведомление «Ящик готов» в кабинет, Telegram и на личный email.

## Вариант B: managed-провайдер (запасной вариант)

1. Зарегистрируйте организацию у провайдера и подтвердите домен `dragotop.ru` — проверочной TXT-записью из его
   админки.
2. Добавьте в REG.RU записи MX, SPF, DKIM и DMARC провайдера (см. [dns-records.md](dns-records.md), раздел B).
   **Значения берите из админки провайдера** — они могут отличаться от примеров.
3. В `.env`: `MAIL_PROVIDER=manual`.
4. Исходящие письма сайта (приглашения, сброс пароля, уведомления) отправляйте через SMTP провайдера со служебного
   ящика `noreply@dragotop.ru`: `SMTP_HOST`, `SMTP_PORT=465`, `SMTP_SECURE=true`, `SMTP_USER`, `SMTP_PASSWORD` — пароль
   приложения.
5. `webmail.dragotop.ru`: скопируйте `infrastructure/mail/webmail-redirect.caddy.example` в
   `infrastructure/caddy/sites/webmail.caddy` и укажите URL веб-почты провайдера. Добавьте запись `A webmail → IP` и
   выполните `make deploy`.
6. В админке `/admin/mail` заводите адреса. Сам ящик создавайте у провайдера, используя его функцию приглашения:
   так пароль задаёт сам боец. После этого отметьте ящик активным.
7. Выполните проверки из раздела «Проверка» ниже.

## Вариант A: свой сервер Stalwart (только сервер без панели)

1. `make preflight-mail` — должен быть открыт порт 25, PTR указывать на `mail.dragotop.ru`, IP не должен быть в
   блок-листах. **Если есть хотя бы один ✘, не продолжайте.** Порт 25 и PTR настраиваются в панели или через
   поддержку хостинг-провайдера VPS.
2. DNS: раздел A в [dns-records.md](dns-records.md). DKIM добавляется после генерации ключа в Stalwart (шаг 5).
3. `sudo bash infrastructure/scripts/02-bootstrap.sh --with-mail` — откроет в UFW порты 25, 465, 587 и 993.
4. `.env`: `MAIL_PROVIDER=stalwart`, `STALWART_URL=http://stalwart:8080`. Затем `WITH_MAIL=1 make deploy`.
5. Первичная настройка Stalwart (админка наружу не публикуется, доступ через SSH-туннель):
   ```bash
   # пароль администратора, сгенерированный при первом запуске:
   docker compose --project-directory infrastructure -f infrastructure/docker-compose.yml -f infrastructure/mail/docker-compose.mail.yml logs stalwart | grep -i password
   # туннель к админке:
   ssh -L 8080:$(docker inspect -f '{{range.NetworkSettings.Networks}}{{.IPAddress}}{{end}}' drago-stalwart-1):8080 root@2.56.90.240
   # открыть http://localhost:8080
   ```
   - Server → Hostname: `mail.dragotop.ru`; добавьте домен `dragotop.ru`.
   - TLS: используйте сертификат, выпущенный Caddy, — он смонтирован в `/caddy`:
     `/caddy/certificates/acme-v02.api.letsencrypt.org-directory/mail.dragotop.ru/mail.dragotop.ru.crt` (и `.key`).
     Caddy обновляет сертификат примерно раз в 60 дней, поэтому добавьте в cron еженедельный
     `docker compose ... restart stalwart` или перезагрузку сертификатов через API Stalwart.
   - DKIM: сгенерируйте RSA-2048 ключ с селектором `drago` и опубликуйте TXT `drago._domainkey`.
   - Антиспам: включите встроенный спам-фильтр, DNSBL и greylisting.
   - Создайте API-ключ или пользователя для управления аккаунтами и пропишите его в `.env`:
     `STALWART_ADMIN_USER` / `STALWART_ADMIN_PASSWORD`.
   - Для пользователей включите 2FA (TOTP) и пароли приложений.
6. Служебный ящик `noreply@dragotop.ru` для писем сайта: `SMTP_HOST=stalwart`, `SMTP_PORT=587`,
   `SMTP_SECURE=false` (STARTTLS).
7. Проверьте состояние провайдера в `/admin/integrations` («Stalwart API доступен») и создайте тестовый ящик.

> Формат API Stalwart проверялся по документации v0.10–0.13. При обновлении Stalwart сверьте `/api/principal`.
> Вся логика изолирована в `StalwartProvisioner`.
