# Безопасность и защита персональных данных

В системе хранятся персональные данные несовершеннолетних. Принципы: **privacy by design**, **минимизация данных**,
**проверка прав на сервере**, **журналирование чувствительных действий**.

## Реализованные меры

| Требование | Реализация |
|---|---|
| CSRF | Server Actions: встроенная проверка Origin/Host в Next.js. `proxy.ts` дополнительно отклоняет любые не-GET запросы без Origin или с чужим Origin. Cookie `SameSite=Lax` |
| XSS | React-экранирование; Markdown из CMS санитизируется (`sanitize-html`, allowlist тегов и схем, без `javascript:`); строгий CSP с nonce и `strict-dynamic` на каждый запрос; JSON-LD экранируется |
| SQL-инъекции | Только Prisma с параметризацией; единственный raw-запрос (воркер) — tagged template с параметрами |
| Brute force | Rate limit в Redis: вход 30/10 мин с IP и 8/15 мин на email; блокировка аккаунта на 30 мин после 10 ошибок подряд; лимиты на 2FA (6/5 мин с завершением сессии), сброс пароля, заявки (5/ч с IP), команды ботов |
| Session fixation | Новый токен при каждом входе; ротация сессии после 2FA; завершение всех сессий при смене/сбросе пароля, смене роли, блокировке, сбросе 2FA |
| Перечисление аккаунтов | Одинаковые ответы при входе и восстановлении; dummy-hash выравнивает время; открытой регистрации нет |
| Пароли | Argon2id; политика ≥10 символов, буквы и цифры; пароль не может содержать email; администраторы паролей не видят и не задают (только ссылки-приглашения и сброс) |
| 2FA | TOTP с защитой от повтора; резервные коды хранятся хэшами; обязательна для командного состава |
| Cookies | `__Host-` префикс, `HttpOnly`, `Secure`, `SameSite=Lax` |
| Заголовки | CSP, HSTS (2 года, preload), `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP/CORP |
| Загрузки | Лимиты размера (15/25 МБ); тип определяется по сигнатуре файла, а не по расширению; белый список (изображения, PDF, OOXML, ODF); изображения перекодируются в WebP с удалением EXIF/GPS; случайные имена; защита от path traversal |
| Доступ к файлам | Внутренние файлы отдаются только через `/api/files/:id` с проверкой прав по сущности-владельцу (документ, объявление, задача); при отсутствии прав — 404; `Content-Disposition` и `CSP: sandbox` на ответах |
| Минимизация данных | Анкета содержит только ФИО, возраст, контакт и опционально Telegram, VK, школу, комментарий. Публичного списка бойцов нет. Контакты бойцов видит только командный состав (`users.read`). В мессенджеры уходят имя и возраст, контакты — только в админке |
| Сроки хранения | Заявки удаляются через N дней (по умолчанию 365), журнал аудита — через 730 дней; истёкшие сессии, токены и временные пароли чистит воркер |
| Аудит | `AuditLog`: актор, действие, сущность, id, время, IP, метаданные (без секретов). Пишутся вход и ошибки входа, 2FA, пользователи (создание, роль, блокировка, удаление, сброс 2FA), новости, документы, настройки, интеграции, почта, заявки, привязки мессенджеров |
| Секреты | Только в `.env` на сервере (права 600, в `.gitignore`); `gen-secrets.sh` генерирует их через `openssl rand`; TOTP-секреты и временные почтовые пароли зашифрованы AES-256-GCM |
| Сеть | Наружу только 80/443 (+ почтовые порты при почте на сервере); в режиме ISPmanager web и vk-bot слушают только 127.0.0.1, а nginx панели перезаписывает `X-Forwarded-For`; PostgreSQL и Redis — в `internal`-сети без портов; Redis с паролем |
| Контейнеры | Процессы от пользователя `node`; `read_only` FS, `cap_drop: ALL`, `no-new-privileges`, лимиты памяти, ротация логов |
| Боты | Telegram: пользователь идентифицируется только по числовому user ID; привязка — одноразовым 192-битным токеном с TTL 10 мин; только личные чаты; дедупликация `update_id`. VK: проверка `group_id` и секрета (constant-time), `confirmation`, дедупликация `event_id`, лимит тела 64 КБ, ответ «ok» до обработки |

## Сервер: рекомендации и скрипты

| Мера | Скрипт | Примечание |
|---|---|---|
| Аудит состояния без изменений | `00-server-audit.sh` | запускать первым |
| Бэкап всего существующего | `01-backup-existing.sh` | `/etc`, `/var/www`, дампы БД, тома Docker |
| UFW: deny incoming, разрешены SSH/80/443 | `02-bootstrap.sh` | порт SSH разрешается **до** включения UFW — доступ не теряется |
| fail2ban: sshd (aggressive) + recidive | `02-bootstrap.sh` | бан 1 ч, повторные нарушители — 1 неделя |
| Автообновления безопасности | `02-bootstrap.sh` | `unattended-upgrades` |
| SSH: только ключи | `03-harden-ssh.sh` | отдельный шаг; проверяет наличие ключей, требует подтверждения, валидирует `sshd -t`, есть откат |
| Отдельный пользователь для деплоя | вручную | `adduser drago && usermod -aG docker drago`; deploy-ключ только для GitHub Actions |
| **Сервер с ISPmanager** | `02-bootstrap.sh` определяет панель сам | UFW не ставится — правила в брандмауэре панели; порт 1500 только с IP администраторов; для почтового API — отдельный пользователь панели (не root); после изменений брандмауэра — `systemctl restart docker` |

Рекомендуется также:

- ключи `ed25519` с парольной фразой; у каждого администратора свой ключ;
- (опционально) сменить порт SSH после hardening — сначала `ufw allow <новый>/tcp`;
- настроить внешний мониторинг доступности (например, UptimeRobot) для `https://dragotop.ru/api/health`;
- регулярно копировать бэкапы с сервера — см. [operations.md](operations.md).

## 152-ФЗ и несовершеннолетние (организационные меры)

Технически система минимизирует данные. Юридическую сторону должен закрыть оператор ПДн — организация, к которой
относится отряд:

1. **Локализация:** персональные данные граждан РФ должны храниться в БД на территории РФ. **Проверьте, что VPS
   2.56.90.240 физически находится в России.** Если нет — перенесите сервер или получите консультацию юриста.
2. **Уведомление Роскомнадзора** об обработке ПДн (если оператор ещё не уведомлял) и назначение ответственного за обработку.
3. **Согласия:** заявки на вступление сайт не собирает — их принимает МосРСО в своём приложении ВКонтакте.
   Для трудоустройства и публикации фото/ФИО несовершеннолетних нужны письменные согласия законных представителей —
   они оформляются офлайн, система их не заменяет.
4. **Политика обработки ПДн** (`/privacy`) — текст-шаблон, его нужно согласовать с оператором.
5. **Фото:** публикуйте фото подростков только с согласия. При загрузке метаданные (геолокация) удаляются автоматически.
6. **Права субъекта:** запросы на доступ или удаление данных выполняются через админку (удаление пользователя, заявки).

## Реагирование на инциденты

1. Подозрение на компрометацию аккаунта: `/admin/users/:id` → «Завершить все сессии», сброс 2FA, ссылка сброса пароля.
2. Утечка `.env`: сменить все секреты (пароли БД и Redis, токены ботов, секрет VK, SMTP) и перезапустить стек.
   `APP_ENCRYPTION_KEY` сменить нельзя без перевыпуска 2FA всем пользователям: сбросить 2FA и попросить настроить заново.
3. Проверить `/admin/audit` и логи Caddy (`/data/logs/access.log` в томе `caddy_data`).
4. Восстановить данные из бэкапа: `make restore f=...`.
