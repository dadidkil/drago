# Роли и права (RBAC)

Источник истины — `packages/shared/src/rbac.ts`. Сид заполняет таблицы `Role`, `Permission` и `RolePermission`.
SUPERADMIN может менять матрицу в `/admin/settings`: изменения применяются во всех сервисах в течение 30 секунд.
Роль SUPERADMIN всегда имеет все права.

## Дополнительные правила (не отключаются матрицей)

- **Иерархия.** Управлять пользователем или назначать роль можно только при уровне строго ниже своего. Исключение —
  SUPERADMIN. Командир не может повысить себя, назначить другого командира или изменить комиссара уровнем выше.
  Над своим аккаунтом административные действия не выполняются.
- **Роли без `users.roles`** (например, комиссар, если ему дать `users.manage`) могут назначать только FIGHTER и CANDIDATE.
- **Блокировка и архивирование** требуют `users.delete`.
- **Аудитория контента** задаётся минимальным уровнем роли: 10 — все, включая кандидатов; 20 — бойцы и выше; 40 —
  командный состав; 60 — командир и комиссар. Правило действует для объявлений, мероприятий и категорий документов.
  У документа может быть свой, более строгий уровень.
- **Кандидаты** видят в списке отряда только командный состав. **Контакты** бойцов (email, телефон, Telegram) видны
  только с правом `users.read`.
- **Обязательная 2FA для уровня ≥ 40:** настройка «Требовать 2FA для командного состава» включена по умолчанию.
  Без 2FA админка недоступна, а server actions админки отклоняются.

## Где проверяется

- Страницы админки: `requireAdmin(permission)` в каждой странице.
- Server Actions: `userAction({ permission })` → `authorize()`. Права проверяются на сервере при каждом вызове,
  скрытие кнопок в UI — только косметика.
- Файлы: `/api/files/[id]` — проверка по сущности-владельцу.
- Боты: `ctx.linked.can(permission)` в каждой командной функции.
